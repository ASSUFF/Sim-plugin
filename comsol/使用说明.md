## 查 Java 类型名

```text
.venv\Scripts\python.exe -m sim_plugin comsol search TemperatureBoundary --limit 20
```

`create_type` 用于 Java 的 `create`。几何类型通常来自 XML 标签，例如 `Block`、`Rectangle`。物理场特征的 XML 标签可能是散列，这时 `create_type` 来自 `name` 属性，例如 `TemperatureBoundary`。属性散列不是 Java 属性名。

## 校验

```text
.venv\Scripts\python.exe -m sim_plugin comsol validate --java comsol\examples\SteadyHeat.java --spec comsol\examples\steady_heat.json
```

Java 需要一个与文件名相同的 public class、`ModelUtil.initStandalone`、`model.param().set`、`===RESULT===` 和 `名字=数值`，以及 `model.save`。规格格式：

```json
{
  "parameters": {
    "T_hot": {"value": "400[K]", "min": 320, "max": 500}
  },
  "exports": ["T_avg_K"],
  "goal": {"expression": "T_avg_K", "sense": "min"}
}
```

`goal` 在单次运行时可以不写。扫描和寻优必须写。目标结果必须能转成数字。

## 运行

```text
.venv\Scripts\python.exe -m sim_plugin comsol run --java comsol\examples\SteadyHeat.java --spec comsol\examples\steady_heat.json --stoptime 180
```

插件把 Java 复制到 `comsol/runs/时间_类名`，用规格里的 `value` 替换副本中的 `model.param().set`，再编译和批处理。原始脚本不变。

`SteadyHeat` 是一块方板的稳态导热：左边 `T_cold`，右边 `T_hot`，另外两边绝热。2026-11-13 14:19 的结果是 `T_avg_K=350`、`T_max_K=400`、`T_min_K=300`，与两端温度的算术平均一致。

光学加热例子是光束进入吸收介质，再把吸收的功率交给传热：

```text
.venv\Scripts\python.exe -m sim_plugin comsol run --java comsol\examples\OptoHeat.java --spec comsol\examples\opto_heat.json --stoptime 240
```

左边入射光强 `I_beam`，方向沿 x。介质吸收系数 `kappa`。左右边界温度固定为 `T_amb`。2026-11-13 14:31 的最高温度是 307.794410 K，一维解析解是 307.794102 K。出口光强约 367.88 W/m²，等于 1000 乘以 exp(-1)。

`--stoptime` 默认 600 秒，最大 7200 秒。

## 扫描

在规格中增加 `sweep`。每个参数 2 到 8 个字符串取值，全部组合不超过 8 次。

```json
"sweep": {"T_hot": ["320[K]", "400[K]", "480[K]"]}
```

```text
.venv\Scripts\python.exe -m sim_plugin comsol sweep --java comsol\examples\SteadyHeat.java --spec 规格.json --stoptime 180
```

## 寻优

```text
.venv\Scripts\python.exe -m sim_plugin comsol optimize --java comsol\examples\SteadyHeat.java --spec comsol\examples\steady_heat_optimize.json --stoptime 180
```

`optimize` 只搜索一个参数。先计算区间两端和中点，再在当前最好点与相邻点之间取中点。`max_runs` 为 2 到 8。

2026-11-13 14:21 对 `T_hot` 在 320 K 到 480 K 之间做了 4 次，目标是最小 `T_avg_K`。最好结果是 `T_hot=320[K]`，`T_avg_K=310`。它落在搜索区间的低端。

`best` 只表示已计算各次中的最好结果。

## 建议事实

```text
.venv\Scripts\python.exe -m sim_plugin comsol advise --report comsol\runs\某次\report.json
```

返回 `facts`。AI 根据这些事实写建议，不把单次求解说成最优，并在最好点位于区间端点时说明扩大区间可能还有更好的点。
