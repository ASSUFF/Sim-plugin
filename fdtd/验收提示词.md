把下面分隔线之间的正文整段复制到 WorkBuddy。工作区请打开插件根目录，也就是含有 `pyproject.toml` 的目录。

---

你在本机验收 FDTD 插件，不是来重写它。请实际执行命令，用这次运行返回的 JSON 下结论。交接文档里的旧数字只作对照，不能代替你自己的运行结果。这里的 FDTD 是 Ansys Lumerical FDTD，不是 Meep。

工作目录：插件根目录  
解释器：插件根目录下的 `.venv\Scripts\python.exe`  
先读 `fdtd\使用说明.md` 和 `fdtd\agent\SKILL.md`。若会话里已有 `fdtd_doctor`、`fdtd_validate`、`fdtd_prepare`、`fdtd_run`、`fdtd_sweep`、`fdtd_optimize`、`fdtd_advise`，用这些工具；否则在终端运行下面的命令。系统自带的 `python` 不在 PATH 上，不要用它。

约束：

- 一次只跑一个会启动 Lumerical 的命令，等它结束再跑下一个。
- 不要修改 `fdtd\examples`、`fdtd\src` 和 `S:\simulation\FDTD\ai`。新建的规格只放在 `fdtd\runs\acceptance\`。
- 不要运行 `fdtd\examples\crossing_sin.json`。那是三维模型，这次不验收。
- 不要设置 `LUMERICAL_FDTD_INTEGRATION`，也不要跑单元测试来代替下面的命令。
- 不要关闭已经打开的 Lumerical、COMSOL 或 Electronics Desktop。
- 这次不验收 COMSOL 和 HFSS。
- 长度用米，时间用秒。透射用 `metric.goal` 为 `max`。`best` 只表示已计算各次中的最好结果。

按顺序做。`doctor` 的 `installed` 不是 true，或求解返回 `stage` 为 `install` 时，停下来，只报告这一步。某一步的错误里出现 license 或 `Session not found` 时，也停下来，不要重试，不要反复启动许可证或求解器。

1. 安装检查，不启动求解器。

```text
.venv\Scripts\python.exe -m sim_plugin fdtd doctor
```

通过标准：`ok` 为 true，`installed` 为 true，`launched_solver` 为 false，`lumapi` 指向一个存在的 `lumapi.py`。2026-11-18 曾找到 `S:\Program Files\Lumerical\v241`，以你这次的 JSON 为准。

2. 校验二维烟雾规格，不求解。

```text
.venv\Scripts\python.exe -m sim_plugin fdtd validate --spec fdtd\examples\smoke_2d.json
```

通过标准：`ok` 为 true，`errors` 为空，`launched_solver` 为 false。

3. 补缺省，不求解。新建 `fdtd\runs\acceptance\partial.json`，内容只写 `{"name": "partial"}`，然后：

```text
.venv\Scripts\python.exe -m sim_plugin fdtd prepare --spec fdtd\runs\acceptance\partial.json
```

通过标准：`ok` 为 true，`launched_solver` 为 false，`assumptions` 里写明补了波长或仿真区域。不要把补完的规格拿去求解。

4. 确认超过 8 个扫描值会被拒绝，且不启动求解器。新建 `fdtd\runs\acceptance\sweep_9.json`：`base` 用 `{"name": "too_many"}`，`parameter` 为 `{"object": "waveguide", "property": "y span"}`，`values` 放 9 个数字，`metric` 为 `{"export": "T", "goal": "max"}`。然后：

```text
.venv\Scripts\python.exe -m sim_plugin fdtd sweep --spec fdtd\runs\acceptance\sweep_9.json
```

通过标准：`ok` 为 false，`launched_solver` 为 false，`stage` 为 `spec`，错误文本说明取值必须是 2 到 8 个。

5. 求解二维偶极子烟雾模型。

```text
.venv\Scripts\python.exe -m sim_plugin fdtd run --spec fdtd\examples\smoke_2d.json
```

通过标准：`ok` 为 true，`launched_solver` 为 true，`exports` 里有 `name` 为 `T` 的一项，并且没有 `export_errors`。记下 `run_dir`、`summary_path` 和 `T` 的数值。这一步没有规定 `T` 必须等于某个旧数字。`fdtd\examples\smoke_2d.json` 保持原样。这一步失败就不要再跑第 7、8、10 步。

6. 对第 5 步的 `summary_path` 取建议事实，不求解。

```text

```

通过标准：`launched_solver` 为 false，事实里说明这是一次求解，并写出导出名称。请只用这些事实写两句建议，不要把这一次叫成最优。

7. 用 override 改监视器位置后再求解。把 `fdtd\examples\smoke_2d.json` 复制为 `fdtd\runs\acceptance\smoke_2d_override.json`，只增加：

```json
"overrides": [{"object": "monitor", "property": "y", "value": 2.0e-7}]
```

然后：

```text
.venv\Scripts\python.exe -m sim_plugin fdtd run --spec fdtd\runs\acceptance\smoke_2d_override.json
```

通过标准：`ok` 为 true，`exports` 里仍有 `T`。`fdtd\examples\smoke_2d.json` 里的监视器 `y` 仍是 `0.4e-6`，且没有 `overrides`。

8. 扫描波导宽度。规格已经是 `fdtd\examples\sweep_wg_width.json`：`y span` 取 `2.0e-7` 和 `5.0e-7` 米，目标是 1550 nm 透射最大。

```text
.venv\Scripts\python.exe -m sim_plugin fdtd sweep --spec fdtd\examples\sweep_wg_width.json
```

通过标准：返回 2 个 `points`，两次 `ok` 都为 true，两次 `score` 都是数字。`best.value` 是分数较大的那一个宽度。把完整 JSON 另存为 `fdtd\runs\acceptance\sweep_report.json`，因为这条命令不会自己写 `report.json`。向我说明 `best` 只是这两个宽度里的最好结果。两个值都在区间端点上，要说明扩大区间可能还有更高的透射。

9. 用第 8 步保存的报告取建议事实，不求解。

```text
.venv\Scripts\python.exe -m sim_plugin fdtd advise --report fdtd\runs\acceptance\sweep_report.json
```

通过标准：`launched_solver` 为 false，事实里有目标、样本数、best，以及端点说明。请只用这些事实写两三句建议。

10. 宽度寻优，最多 3 次。新建 `fdtd\runs\acceptance\wg_width_optimize.json`：`base`、`parameter`、`metric` 与 `fdtd\examples\sweep_wg_width.json` 相同，把 `values` 换成：

```json
"optimize": {"min": 2.0e-7, "max": 5.0e-7, "max_runs": 3}
```

然后：

```text
.venv\Scripts\python.exe -m sim_plugin fdtd optimize --spec fdtd\runs\acceptance\wg_width_optimize.json
```

通过标准：`run_count` 为 3，每次都有数字 `score`。`best.value` 是这 3 次里透射最高的宽度。返回里的 `note` 要说明这不是没算过的宽度上的全局最优。记下 `report`。`best.value` 若是 `2.0e-7` 或 `5.0e-7`，还要说明它落在区间端点。

11. 用第 10 步的 `report` 再取一次建议事实。通过标准：`launched_solver` 为 false，事实包含目标和最好取值。请用这些事实写两三句建议。
