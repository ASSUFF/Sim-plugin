# HFSS 使用说明

最后更新：2026-11-23。总说明见插件根目录的 `使用说明.md`，英文见 `README.md`。

在插件根目录执行。长度用米，频率用赫兹。矩形波导后端在 `hfss/src/hfss_aedt`。`doctor` 不需要 PyAEDT。求解需要当前 Python 能 `import ansys.aedt.core`，否则执行 `pip install pyaedt`。`HFSS_AEDT_PYTHON` 和 `HFSS_AEDT_SRC` 只用于换一份后端；指向不存在的文件时返回 `stage` 为 `backend`。当前后端只能建立直矩形波导并返回 S 参数，不能返回 Neff 或 Z0。`geometry.modes` 默认 1，最大 4；大于 1 时结果名是 `dB(S(P2:2,P1:1))` 这种带模式号的写法，单模仍是 `dB(S(P2,P1))`。`geometry.wall` 默认 `pec`。铜、金、铝、银使用内置电导率，`finite` 要另给 `wall_conductivity_s_m`，单位是西门子每米。有限电导率加在两个端口以外的壁上。一条谱用 `frequency_sweep`，包含 `start_hz`、`stop_hz` 和 `count`（2 到 201），`type` 默认 `Discrete`。它和自适应用的 `frequency_hz` 一起放在同一次求解里，多频点写入 `s_spectrum.csv`，不占用 8 次独立求解。只取回一个频点时，`export_errors` 会写明谱没有生成。`frequencies_hz` 仍是检查表里的 1 到 21 个离散频点，不是这条谱。材料不在内置名单里时，顶层要写 `material_verified: true`。材料名不在 `vacuum`、`air`、`pec`、`copper`、`gold`、`aluminum`、`silver`、`teflon` 中时，求解不会开始，除非规格里 `material_verified` 为 true。打开已有工程必须写 `design`。规格里的 `expect` 可给结果设上下限；结果不是有限数值时 `ok` 为 false。插件不使用某一台电脑上的固定目录。结果目录用规格里的 `run_root` 或环境变量 `HFSS_AEDT_RUNS`。目录里有中文等非 ASCII 字符时，AEDT 在临时 ASCII 目录求解，结束后把工程、Touchstone、频谱和结果目录拷回 `run_dir`。保存仍然失败时 `stage` 为 `path`。结果里的 `solver` 给出 `frequency_count`、`max_passes`，以及从求解文件读到的 `mesh_tets`。`doctor` 检查运行目录是否含非 ASCII、是否在 OneDrive 或网络盘，以及临时目录能否写入。求解失败时 `log_tail` 是输出的最后 20 行。

用户第一次把任务完整说出来时，先整理需求并补上频率、几何、材料、求解区域和自适应精度。执行 `hfss confirm --spec 草稿.json`，它不启动 Electronics Desktop。用户同意后，把返回的 `spec` 交给 `run`、`sweep` 或 `optimize`。没有确认时这三条不启动求解器。报告里的 `assumptions` 是确认清单中 `source` 为 `assumed` 的项。扫描和寻优的 `rows`、`best` 与 COMSOL 相同。

已有 `.aedt` 先复制到 `hfss/runs`，原文件不覆盖。

```text
.venv\Scripts\python.exe -m sim_plugin hfss inspect --project 模型.aedt
.venv\Scripts\python.exe -m sim_plugin hfss set --project 模型.aedt --spec 改动.json
```

`inspect` 返回对象、求解设置和设计变量名，不求解。要改的量写在规格的 `variables` 里，键用返回的变量名。`set` 只把这些量写入副本。

不启动 Electronics Desktop 的命令：

```text
.venv\Scripts\python.exe -m sim_plugin hfss doctor
.venv\Scripts\python.exe -m sim_plugin hfss validate --spec hfss\examples\wr90.json
.venv\Scripts\python.exe -m sim_plugin hfss prepare --spec 一份缺少尺寸的规格.json
```

会求解的命令：

```text
.venv\Scripts\python.exe -m sim_plugin hfss run --spec hfss\examples\wr90.json
.venv\Scripts\python.exe -m sim_plugin hfss sweep --spec hfss\examples\wr90_length_sweep.json
```

`validate` 校验的是单次求解规格。扫描可以沿用单个 `parameter.path` 和 `values`。多参数写在 `sweep` 里，例如 `{"geometry.length_m": [0.02, 0.03], "frequency_hz": [8e9, 1e10]}`。每个参数 2 到 8 个值，组合不超过 8 次，否则 `stage` 为 `spec`。没有点的键直接写到规格上，带点的键按路径写入，设计变量用 `variables.名称`。求解前检查自适应次数、收敛标准和频点；不通过时 `stage` 为 `checklist`。许可证连不上时 `stage` 为 `license`，错误里只有一个下一步，不会再次启动许可证服务。

`validate` 校验的是单次求解规格。扫描规格由 `sweep` 自己检查：`base` 是一次仿真规格，`parameter.path` 例如 `geometry.length_m`，`values` 为 2 到 8 个数值，`metric.goal` 为 `max` 或 `min`。S21 用 `max`，S11 用 `min`。返回的 `rows` 与 `best` 各含 `parameters`、`ok`、`results`、`work_dir`、`error`，`goal` 为 `expression` 与 `sense`。

2026-11-18 的长度扫描在 `hfss\runs\20261118_122726_wr90_length_sweep_sweep`。10 GHz 时三档 S21 都是 -0.0 dB；S11 为 -69.985 / -64.084 / -67.465 dB。`best` 是 0.02 m。它落在 0.02–0.04 m 的低端，扩大区间后还可能有更好的点。

长度寻优和建议事实：

```text
.venv\Scripts\python.exe -m sim_plugin hfss optimize --spec hfss\examples\wr90_length_optimize.json
.venv\Scripts\python.exe -m sim_plugin hfss advise --report hfss\runs\某次\report.json
```

`optimize` 先取区间两端和中点，再在当前最好点旁边取中点，总共不超过 `max_runs`，且最多 8 次。`advise` 不启动 HFSS。

结果写在 `hfss\runs`。源工程先复制再改。不关闭已经打开的 Electronics Desktop。设置 `HFSS_PROTECTED_PROJECT` 可以禁止打开或复制某一个工程。
